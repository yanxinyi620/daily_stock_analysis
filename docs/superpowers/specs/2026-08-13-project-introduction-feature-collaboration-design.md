# 项目介绍：功能协同章节设计

## 目标

在“系统能做什么”和贵州茅台案例之间新增一章，说明选股、每日综合分析、单股分析、问股、回测、自选股与提醒为什么会出现在同一个系统中，以及用户怎样在这些功能之间继续研究。

## 章节结构

1. 直接说明协同关系：各功能不是重复生成报告，而是分别负责发现、分析、追问、验证和继续跟踪。
2. 一张六步循环图：选股 → 每日综合分析 → 单股分析 → 问股 → 回测 → 自选股与提醒 → 下一次每日分析。
3. 一张功能衔接表：每项功能的输入、解决的问题、输出和常见下一步。
4. 一个贵州茅台简短示例，说明如何从综合报告发现关注对象，进入单股报告，继续追问，查看历史表现，再决定是否加入提醒。
5. 明确边界：这是研究流程，不是自动交易闭环；选股不等于买入，回测不保证未来，部分步骤由用户主动触发。

## 事实边界

- 选股候选可以继续进入单股分析。
- 每日综合分析面向自选股，可包含个股执行、大盘复盘和综合报告。
- 问股可对分析继续提问；不同问股运行方式可使用的实时工具不同。
- 回测用于查看历史任务与结果，验证历史判断或规则，不预测未来。
- 自选股可批量分析，提醒中心用于继续跟踪条件。
- 不声称六步已经完全自动串联，也不声称回测结果会自动修改策略。

## 视觉与语言

- 沿用现有暖纸色研究报告风格。
- 循环图在桌面横向排列，手机端改为纵向。
- 使用具体中文动作，不使用“能力协同矩阵、生态闭环、智能联动”等抽象或宣传表达。

## 验收标准

- 新增 `feature-collaboration` 章节与目录入口。
- 页面出现六个功能步骤及循环关系图。
- 功能表同时包含输入、主要用途、输出和下一步。
- 包含贵州茅台串联示例和三项边界声明。
- 原八步报告案例、历史数字、离线、响应式、打印和无脚本行为保持不变。
