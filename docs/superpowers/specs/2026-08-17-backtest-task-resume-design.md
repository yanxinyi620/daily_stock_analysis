# 回测任务刷新恢复设计

## 目标

刷新回测页面后，从服务端恢复仍在运行的回测任务，继续显示运行状态并阻止重复提交；任务完成后刷新结果与统计。

## 设计

- 后端提供当前活动回测任务查询，返回与单任务状态接口相同的结构；没有活动任务时返回 `null`。
- 前端 API 将任务提交、单次状态查询、活动任务查询和轮询分开；新提交与页面恢复共用同一轮询函数。
- 页面初始化时查询活动任务。发现 `pending` 或 `processing` 后设置运行态并等待完成；完成后恢复结果摘要并刷新列表和统计。
- 状态以服务端任务队列为唯一真源，不使用 `localStorage`。服务重启导致内存任务消失时，页面按“当前无任务”处理。

## 边界

- 同一服务进程只允许一个活动回测任务；重复提交继续复用现有任务。
- 不恢复已经完成的旧任务，不删除回测数据，不修改回测筛选条件。
- 查询失败不阻断页面现有结果加载；仅按普通页面错误处理。

## 验证

- 后端测试活动任务存在与不存在两种返回。
- 前端 API 测试恢复活动任务并轮询到完成。
- 页面测试挂载时恢复“回测中”，按钮禁用，完成后刷新数据。
