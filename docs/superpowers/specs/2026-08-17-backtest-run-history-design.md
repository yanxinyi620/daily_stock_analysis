# 回测运行历史设计

## 目标

为 Web/API 发起的回测任务保存轻量运行记录，让用户能追溯每次运行使用的参数、时间、状态和结果汇总，并可按相同参数重新运行。

## 数据边界

新增 `backtest_runs` 表，与逐条验证结果 `backtest_results` 分离。运行记录保存：运行 ID、任务 ID、来源、状态、股票范围、日期范围、评估窗口、最小天龄、强制重跑、处理上限、创建/开始/完成时间、处理/保存/完成/数据不足/错误数量、可读消息、低敏诊断和失败原因。不复制行情、个股结果或完整日志。

## 生命周期

- 新异步任务被接受后写入 `pending` 记录；复用已有活动任务时不新增记录。
- 后台执行开始时更新为 `processing`。
- 正常返回时按错误数量标记 `completed` 或 `partial`，并保存汇总。
- 异常时标记 `failed`，保存经过收敛的失败说明后继续让任务队列处理异常。
- 同步 `/run` 兼容接口也保存一条 `api_sync` 运行记录。

## API 与页面

- `GET /api/v1/backtest/runs` 分页返回运行历史，按创建时间倒序。
- 回测页在“回测结果”旁增加“运行历史”切换。
- 历史列表展示时间、状态、参数范围和执行汇总；“按相同参数重新运行”复用正常提交入口及重复任务保护。

## 兼容性

现有数据库启动时通过 SQLAlchemy `create_all` 幂等创建新表；没有旧数据回填。删除新表即可回滚持久化数据，旧回测结果与汇总不受影响。
