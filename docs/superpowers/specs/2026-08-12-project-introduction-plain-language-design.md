# 项目介绍 HTML 通俗化重写设计

## 目标

在不改变贵州茅台历史案例事实、八步流程、技术名称和页面视觉结构的前提下，降低阅读门槛。产品、技术及非技术读者应能快速明白：系统做什么、每一步拿什么数据、用了什么工具、产生什么结果、数据不足时怎么处理，以及最终建议为什么是“观望”。

## 写作原则

1. 先说具体动作，再补技术名称。例如先写“把各类数据整理到一张统一清单”，再标注 `AnalysisContextPack`。
2. 中文状态在前，英文状态放在括号内，例如“部分可用（partial）”。英文仅用于与系统字段对应。
3. 一个句子只表达一个主要意思；拆分超过两层的并列关系。
4. 删除宣传口号和抽象判断，改成读者能核对的事实或动作。
5. 标题直接回答本节内容，不使用“能力地图”“技术底座”“证据边界”等需要再次解释的名称。
6. 八步台账标签改为：这一步要做什么、拿到什么、使用什么、怎样处理、得到什么、数据不足怎么办、接下来交给谁。
7. 图表名称直白化，例如“数据从哪里来、最后到哪里去”“为什么得出这个结论”。
8. 专业术语确实必要时保留，并在第一次出现时用一句中文解释。

## 重点替换

| 原表达 | 改写方向 |
| --- | --- |
| 证据链 / 数据血缘 | 数据从哪里来、经过哪些处理 |
| 证据边界 | 目前有哪些数据、哪些还缺少 |
| 数据质量语义 | 五种数据状态 |
| 确定性证据 | 程序已经计算或核对的数据 |
| 生成式表达 | 模型根据已有数据组织说明 |
| 护栏 | 必须遵守的检查规则 |
| 降级 | 数据不足或工具失败时怎么办 |
| 上下文包 / 可消费 | 给模型使用的统一资料包 |
| 结论溯源 | 为什么得出这个结论 |
| 技术底座 | 系统由哪些部分组成 |
| 失败隔离 | 一个环节失败时，不影响已完成的其他环节 |

## 保留内容

- 贵州茅台（600519）及 2026-08-12 历史案例。
- 所有已核验的行情、均线、评分、仓位、关键价位和数据状态。
- 八步流程及工具名称。
- 最终报告、价格位置图、五种数据状态、结论来源表。
- 离线浏览、响应式、无 JavaScript、减弱动画和打印支持。
- `available`、`partial`、`missing`、`failed`、`empty`，但必须与中文解释同时出现。

## 验收标准

- 首屏和每章标题不依赖抽象词也能理解。
- 页面不再用英文短语承担主要信息。
- 每一步只读中文内容即可理解输入、处理、输出与异常处理。
- 技术名不被删除或错误翻译。
- 历史数字与原报告一致，永鼎股份内容仍然不存在。
- 原有内容合同、移动端、打印、无脚本和本地资源验证继续通过。

## 不在本轮范围

- 不改变页面整体布局、颜色和主要图表。
- 不增加新的产品功能或案例。
- 不修改分析代码、数据源或报告生成逻辑。
