# DSA 移动日常使用端设计

## 1. 目标与边界

在现有 React/FastAPI 应用内增加移动优先的日常使用端。桌面端继续承担高密度报告、复杂回测和系统配置；移动端面向查看结果、发起常用分析、跟踪任务、问股和处理提醒。

第一版必须支持：

- 五个固定底部入口：`首页`、`自选`、`问股`、`任务`、`我的`。
- 查看个股、综合分析、大盘复盘、AI 建议、持仓和告警摘要。
- 发起单股分析、综合分析、选股和问股。
- 查看任务进度、完成结果和失败原因。
- 保留主题、语言、通知等日常设置入口；模型渠道、API Key、数据源和高级回测配置继续由桌面端管理。

第一版不开发微信小程序、React Native 或原生 App，不复制第二套 API/状态逻辑，也不重写后端任务协议。

## 2. 总体架构

采用同一 React 应用中的双界面壳：

```text
FastAPI / REST / SSE
        │
共享 API、类型、认证、Zustand 状态与报告组件
        │
 ┌──────┴──────────┐
桌面 Shell       MobileShell
侧栏/宽表格       顶栏/底部导航/卡片/抽屉
```

界面壳按 CSS 媒体查询和视口能力切换，不依赖一次性的 `window.innerWidth` 渲染分支，避免服务端测试、旋转屏幕和窗口调整产生状态漂移。桌面路由保持兼容；移动端使用独立的 `/m/*` 路由表达五入口信息架构，同时窄屏访问桌面核心入口时可引导至对应移动路由。`/mobile` 仅作为 `/m` 的兼容重定向。

共享层包括：

- `api/` 请求、字段转换和错误契约。
- `types/` 领域模型。
- `analysisStore`、`stockPoolStore`、`agentChatStore`。
- 报告摘要、任务状态、股票自动补全、认证、主题和语言能力。

移动专属层只负责页面编排、导航、移动卡片和操作布局，不重新实现业务规则。

## 3. 路由和五入口

### 3.1 首页 `/m`

首页是日常决策仪表盘，不复制当前桌面首页全部内容。自上而下展示：

1. 交易日与服务状态。
2. 市场摘要与最近一次大盘复盘。
3. 当前运行任务条和完成提醒。
4. 快捷操作：单股分析、综合分析、选股、大盘复盘。
5. 自选股今日摘要，最多展示 5 条并进入“自选”。
6. 最近报告，默认只显示结论、评分、风险和操作建议。

### 3.2 自选 `/m/watchlist`

整合桌面首页中的自选、今日和历史三个工作区：

- 顶部提供股票搜索与添加。
- 分段切换“自选 / 今日 / 历史”。
- 每只股票使用卡片展示名称、代码、今日状态、操作建议、评分和任务进度。
- 点击卡片进入移动报告详情 `/m/reports/:historyId`。
- 支持单股分析、分析全部、仅分析未完成和移除自选。

### 3.3 问股 `/m/chat`

复用现有会话和消息状态：

- 消息区占据主要高度，输入框吸附底部并位于系统底部导航之上。
- 会话列表、Skill 和股票上下文放入顶部抽屉。
- 支持文本追问、从自选或报告带入股票上下文、显示生成状态和失败重试。

### 3.4 任务 `/m/tasks`

将任务从桌面首页附属面板提升为独立入口：

- 分段展示“进行中 / 已完成 / 失败”。
- 卡片显示任务类型、股票或范围、进度、当前阶段、开始时间和错误摘要。
- 任务完成后可打开对应报告；失败任务提供符合原任务语义的重新运行入口。
- 运行流和 Trace 默认折叠到“诊断信息”，不占据首屏。

### 3.5 我的 `/m/me`

聚合低频能力，不把全部桌面导航塞进底部栏：

- 持仓摘要、AI 建议、告警状态、模型用量。
- 选股入口与最近一次选股结果。
- 主题、语言、通知开关和登录/退出。
- “高级设置请使用桌面端”说明，并提供只读的当前模型、数据源和服务状态。
- 回测第一版只显示最近结果摘要，不提供复杂参数表单。

## 4. 报告与操作体验

移动报告详情统一采用三层信息层级：

1. 首屏结论：股票/报告类型、时间、评分、操作建议、趋势和风险等级。
2. 决策摘要：核心洞察、关键风险、策略点位、数据质量。
3. 完整报告：用户主动展开后渲染 Markdown、图表和运行详情。

主要操作使用底部吸附操作栏，但不得与五入口导航重叠。操作栏只保留当前上下文最重要的 1 个主操作和最多 2 个次操作，其余进入更多菜单。综合报告、大盘复盘和单股报告按各自语义显示操作，不复用不适用的单股按钮。

## 5. 响应式和视觉规则

- 移动壳适用宽度小于 `768px`；`768px` 及以上继续使用现有桌面壳，避免平板横屏被强制压成手机界面。
- 使用 `100dvh`、安全区 `env(safe-area-inset-*)` 和单一内容滚动容器。
- 底部导航最小触控高度 56px，点击目标不小于 44×44px。
- 手机端禁止依赖横向滚动完成核心任务；宽表格转换为卡片或字段分组。完整诊断表格可以作为明确标记的次级横向区域。
- 避免多层独立纵向滚动。抽屉打开时锁定背景滚动。
- 延续当前主题、颜色、圆角和状态色，不创建与桌面端割裂的新品牌视觉。

## 6. 数据流和状态

- `MobileShell` 只维护导航和临时 UI 状态，不保存业务数据。
- 自选与报告继续由 `stockPoolStore` 管理，避免移动/桌面切换后出现两份历史状态。
- 问股继续使用 `agentChatStore`，会话可跨界面壳恢复。
- 任务数据使用现有任务查询和 SSE/轮询契约；抽取共享任务选择器，避免桌面和移动各自解释任务状态。
- 从移动页发起任务后立即跳转或提示进入“任务”，任务完成后链接到持久化历史报告。
- 路由是可分享和可恢复的状态；刷新 `/m/watchlist`、`/m/tasks` 或报告详情不能退回桌面首页。

## 7. 错误、离线和安全

- 网络断开时保留最近已加载数据，并显示“数据可能已过期”，不把旧数据伪装成实时结果。
- 提交任务超时后先查询任务状态，避免重复提交。
- 服务不可达时五入口仍可切换，并提供统一重试；涉及写操作的按钮禁用。
- 移动端不展示 API Key 明文，也不提供模型渠道密钥编辑。
- PWA 缓存只覆盖静态资源和非敏感壳页面，不缓存认证响应、API Key、任务写请求或完整私密报告。

## 8. PWA

在移动界面稳定后加入最小 PWA 能力：

- Web App Manifest、移动图标、主题色和 standalone 显示。
- 静态资源版本化缓存与更新提示。
- 不在第一版实现离线分析、后台模型任务或 Web Push；任务仍由 FastAPI 服务端运行。

## 9. 实施阶段

### 阶段一：移动骨架

- 新增 `/m/*` 路由、`MobileShell`、底部导航、安全区和移动路由错误边界。
- 建立首页、自选、问股、任务、我的五个可导航页面骨架。

### 阶段二：日常闭环

- 接入自选、报告详情、单股/综合分析、问股和任务状态。
- 将宽表格转换为移动卡片，完成失败、加载和空状态。

### 阶段三：辅助能力

- 接入持仓、AI 建议、告警、用量与选股摘要。
- 增加 PWA 安装能力和更新提示。

## 10. 测试与验收

- 单元/组件测试：底部导航、活动路由、五入口数据状态、任务提交、失败重试和报告层级。
- 路由测试：直接刷新所有 `/m/*` 路由、认证重定向和桌面路由兼容。
- Playwright 移动视口：至少覆盖 iPhone 13（390×844）和 Pixel 7（412×915）。
- 视觉验收：浅色/深色、中文/英文、空数据、长股票名、运行中任务、失败任务和长报告。
- 可用性验收：核心操作无横向滚动、底部操作不遮挡导航、输入框不被软键盘/安全区遮挡。
- 回归验证：现有桌面页面测试、lint 和生产构建必须继续通过。

## 11. 完成标准

- 五个底部入口在真实移动视口可达且刷新可恢复。
- 用户能在移动端完成“查看自选 → 发起分析 → 跟踪任务 → 打开报告 → 继续问股”的闭环。
- 用户能发起综合分析和选股，并查看结果或失败原因。
- 高级配置仍由桌面端提供且桌面路由/体验不退化。
- 移动视觉、自动化测试、构建和文档均有可复核证据。
