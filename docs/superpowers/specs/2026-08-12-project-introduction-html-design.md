# DSA 项目介绍 HTML 材料设计说明

## 1. 目标

为 Daily Stock Analysis（DSA）制作一份中文单页 HTML 介绍材料，用于向产品、技术及非技术参与者讲清楚：

- 项目解决什么问题；
- 用户能获得哪些能力和结果；
- 从数据到决策报告的完整流程；
- 系统的主要技术分层、稳定性策略和运行方式；
- 项目的适用场景与能力边界。

材料需要同时满足现场投屏和会后自读。现场讲解目标时长约 17 分钟，预留约 3 分钟交流；自读者无需讲解者补充也能理解整体逻辑。

## 2. 受众与表达原则

### 2.1 主要受众

- 产品与技术混合团队；
- 对项目感兴趣、但不熟悉软件架构或股票分析实现的参与者；
- 希望快速判断项目用途、完成度和技术思路的潜在使用者或协作者。

### 2.2 表达原则

- 先说明问题与价值，再解释产品和技术；
- 每个章节只承载一个主要观点；
- 技术名词出现时同时给出通俗含义，不深入源码、类名或字段契约；
- 使用真实能力和仓库素材，不编造用户量、性能、准确率或覆盖率数据；
- 明确 AI 分析是辅助研判，不构成投资建议，也不替代数据质量判断与人工决策；
- 真实截图用于证明完成度，图解用于解释关系，两者不重复堆叠。

## 3. 叙事结构与讲解节奏

采用“问题 → 流水线 → 产品体验 → 技术底座 → 使用方式 → 能力边界”的用户旅程式故事线。

| 章节 | 内容 | 预计时间 | 主要视觉 |
| --- | --- | ---: | --- |
| 00 开场 | 一句话定位：把分散的市场信息变成可行动的决策 | 1 分钟 | 动态数据流封面 |
| 01 问题 | 数据、新闻、指标和模型分散；人工汇总耗时、难复用、难追踪 | 2 分钟 | 信息碎片汇聚图 |
| 02 完整旅程 | 输入标的 → 汇集事实 → 构建上下文 → AI 研判 → 报告与推送 | 3 分钟 | 逐步点亮的流程图 |
| 03 产品体验 | 决策报告、多市场、Web/桌面工作台、Agent 问股、智能导入、回测持仓、告警与推送 | 3 分钟 | 能力地图 + 真实截图 |
| 04 技术底座 | 入口与触达、流程编排、分析与上下文、报告与通知；补充 fallback 与失败隔离 | 4 分钟 | 分层架构图 |
| 05 运行方式 | GitHub Actions、Docker、本地、Web、Desktop、API 与 Bot | 2 分钟 | 场景化部署路径 |
| 06 边界与结尾 | 自动化、可追踪和持续服务的价值；数据、模型和投资风险边界 | 2 分钟 | 价值闭环与边界提示 |

总讲解时间约 17 分钟。

## 4. 页面与交互模型

### 4.1 页面形式

- 单页、连续滚动的 HTML 材料；
- 每个主章节使用接近一个视口的视觉区块，但不强制固定高度，避免小屏裁切；
- 顶部显示整体阅读进度；
- 侧边或顶部提供简洁章节导航；
- 方向键切换到上一个或下一个主章节，适合现场投屏；
- 点击目录可直接跳转，自读者也可自然滚动；
- 技术章节提供少量补充注解，不设置复杂弹窗或多层交互。

### 4.2 动画

- 首屏使用一次有节奏的标题、数据点和趋势线入场；
- 流程图随章节进入视口逐步点亮节点与连线；
- 架构图使用轻量分层显现，不持续循环干扰阅读；
- 截图只做轻微位移、遮罩揭示或聚焦，不模拟复杂产品操作；
- 支持 `prefers-reduced-motion`，关闭非必要动画并立即展示完整信息；
- 页面核心信息不依赖动画才能理解。

### 4.3 自读与打印

- 正文保持足够上下文，使材料脱离讲解也能成立；
- 讲解提示不直接显示为演讲者备注，避免干扰普通阅读；
- 提供打印样式：取消动画和深色大面积背景、隐藏交互导航、尽量避免章节跨页断裂；
- HTML 不依赖外部图表库或网络字体，保证离线查看稳定。

## 5. 视觉设计

采用确认后的 A × B 混合方向：

- A 的特点：深色、高对比、简洁直观、具有市场决策感；
- B 的特点：编辑式叙事、舒适留白、纸张感浅色区块、系统图鉴式解释；
- 首屏和关键结论章节以深海军蓝为主，使用绿色表示积极趋势、金色表示重要信息；
- 流程、架构和自读内容使用暖米色背景，以深蓝绿和朱红作为结构强调色；
- 避免常见紫色渐变、泛化玻璃拟态和密集仪表盘卡片；
- 标题使用具有编辑感的衬线中文字体回退栈，正文使用清晰的中文无衬线系统字体回退栈；不下载网络字体。

## 6. 内容设计

### 6.1 功能介绍

功能部分按用户获得的结果组织，不按代码模块罗列：

- AI 决策报告：结论、评分、趋势、关键点位、风险警报、催化因素与行动检查清单；
- 多市场数据聚合：A 股、港股、美股、日股、韩股、台股与 ETF，并说明各市场数据能力存在边界；
- Web / 桌面工作台：手动分析、进度、历史报告、完整 Markdown、配置、回测和持仓；
- Agent 策略问股：多轮追问与多种内置分析策略；
- 智能导入和补全：图片、CSV/Excel、剪贴板，以及代码、名称、拼音和别名补全；
- 自动化与触达：GitHub Actions、Docker、本地调度、FastAPI、Bot 与多渠道通知；
- 持续服务能力：规则告警、监控与历史追踪。

### 6.2 技术实现

技术部分使用四层结构，不展开源码细节：

1. 入口与触达：CLI、Web、Desktop、FastAPI、Bot 和 GitHub Actions；
2. 流程编排：任务、并发、进度、调度、历史与异常隔离；
3. 分析与上下文：多源行情、技术指标、基本面、新闻情报、市场阶段、热点、风险和 LLM 综合研判；
4. 报告与通知：结构化结果、Markdown 报告、持久化和多渠道推送。

需要明确传达的实现思想：

- 系统不是把原始数据直接交给模型，而是先完成数据归一、指标计算和上下文构建；
- 多数据源按市场与能力进行适配，并通过 fallback 降低单一上游故障影响；
- 可选搜索、热点或单一通知渠道采用失败开放或失败隔离，避免拖垮主流程；
- 单只股票失败不影响同批次其他标的；
- LLM 负责综合研判和表达，事实来源、技术计算与任务编排由其他模块承担。

### 6.3 运行方式

部署与入口不做配置教程，只按使用场景进行对照：

- 想低门槛定时运行：GitHub Actions；
- 想长期、自主管理：Docker 或服务器部署；
- 想本机体验与开发：本地 Python；
- 想可视化操作：Web 或 Desktop；
- 想系统集成：FastAPI；
- 想在消息应用中使用：Bot 与通知渠道。

## 7. 真实素材选择

主材料只使用三类现有素材：

1. `docs/assets/readme_workspace_tour_20260510.gif`
   - 用途：产品体验章节主画面；
   - 原因：能连续展示 Web 工作台、历史分析和报告操作路径；
   - 处理：保留动画，同时提供静态外观与说明，避免 GIF 成为唯一信息来源。

2. `docs/assets/sample.png`
   - 用途：解释决策仪表盘输出；
   - 原因：结论、风险、利好、点位和检查项集中，适合非技术受众理解成果；
   - 处理：在页面中以裁切或标注方式突出结构，不要求观众阅读全部小字。

3. `docs/assets/alert-center-p5-web.png`
   - 用途：说明规则告警与持续服务；
   - 原因：展示项目从一次性分析延伸到规则、触发历史和通知；
   - 处理：只占一个辅助画面，不展开告警配置细节。

不使用 `docs/assets/fastapi_server.png` 作为主画面，因为其产品视觉与当前工作台素材存在差异；不使用大盘复盘长截图，因为它与报告输出章节信息重复且不适合投屏阅读。

## 8. 文件与实现范围

计划交付：

- `docs/project-introduction.html`：独立可打开的主材料；
- 复用 `docs/assets/` 中已经存在的三项素材，不复制或改写原始文件；
- `docs/CHANGELOG.md` 的 `[Unreleased]` 扁平区新增一条 `[文档]` 记录，因为这是新的用户可见项目介绍材料；
- 不修改 `README.md`，避免首页继续膨胀；
- 不引入 npm、构建步骤、在线图表依赖或新的图片资源；
- 不修改应用功能、API、Schema、配置或部署行为。

HTML 内部包含语义化结构、局部 CSS 和少量原生 JavaScript。图表和架构图使用 HTML/CSS/SVG 原生绘制，所有图形提供文字标签或可访问说明。

## 9. 响应式与可访问性

- 支持常见桌面投屏尺寸，并在 360px 宽度下自然堆叠；
- 正文、图例和关键标注保持可读，不以缩小字体解决布局问题；
- 使用语义化标题顺序、导航链接和原生按钮；
- 所有可点击控件支持键盘聚焦；
- 图片提供准确的 `alt` 文本；
- SVG 图解提供标题或可访问描述；
- 颜色不作为唯一信息编码方式；
- 键盘左右方向键只在非表单控件聚焦时切换章节，避免抢占正常交互。

## 10. 验证方案

实现完成后进行以下验证：

1. 静态检查：确认 HTML 结构完整、资源路径存在、JavaScript 无明显未定义变量；
2. 浏览器验证：在桌面宽度检查章节导航、方向键、滚动进度和动画触发；
3. 响应式验证：至少检查约 1440px、736px 和 360px 三种宽度；
4. 动效验证：检查默认动画和 `prefers-reduced-motion` 两种状态；
5. 离线验证：断开网络或阻止外部请求后，页面内容与素材仍完整显示；
6. 打印验证：检查打印预览或导出 PDF 时的章节分页、背景与导航隐藏；
7. 内容核对：对照 README、文档索引、核心流水线与当前仓库能力，避免功能宣传与实现不一致；
8. 讲解节奏：按章节快速走读一次，确认完整讲解落在 15–20 分钟内。

## 11. 风险与控制

- 功能过多导致材料拥挤：以用户旅程为主线，只展示能力地图，不逐项演示；
- 截图小字在投屏时不可读：只把截图作为场景证据，通过裁切、标题和旁注突出重点；
- 动画干扰自读：动画只在首次进入章节时运行，并支持减弱动画；
- 技术表达太深：架构只保留四层和关键稳定性思想，不出现源码级调用链；
- 技术表达太浅：保留数据归一、上下文构建、fallback、失败隔离和 LLM 职责边界；
- 工作区已有未提交改动：本任务只新增专题 HTML、规格/计划文档并更新变更日志的独立条目，避开现有已修改业务文件。

## 12. 回滚方式

删除本任务新增的专题 HTML、规格/计划文档，并移除 `docs/CHANGELOG.md` 中对应的 `[文档]` 条目即可。现有图片素材不做修改，因此无需恢复。
