# 完整版项目介绍七章重构设计

## 目标

在不大幅删减内容的前提下，将 `docs/project-introduction.html` 从九章重组为七章，使产品、技术与非技术读者都能沿着一条连续主线阅读。

## 七章结构

1. **项目价值**：解决什么问题、适合谁、系统能做和不能做什么。
2. **产品能力与协同**：合并主要功能与功能配合，完整保留选股、每日综合分析、单股分析、问股、回测、自选股与提醒。
3. **系统怎样完成分析**：完整保留八步分析过程、每步输入输出、工具、处理方式、数据不足处理和下一步去向。
4. **贵州茅台完整案例**：集中呈现案例背景、原始数据、数据状态和关键指标。
5. **最终报告与结论依据**：合并报告正文和结论来源，按照结论、数据、判断方法与使用条件连续阅读。
6. **技术实现与系统边界**：说明入口、任务编排、数据与分析、保存与通知，以及失败降级方式。
7. **使用方式与限制**：集中说明运行入口、使用建议、限制和投资风险。

## 内容原则

- 不删除八步分析账本、贵州茅台历史数值、完整报告、结论来源表、系统组成和使用限制。
- 合并重复的章节导语和标题，正文只做必要的通俗化与格式整理。
- 每章开头增加“本章回答”的简短提示。
- 工具名称保留，但采用中文职责说明在前、英文名称在后。
- 完整版与精简版互相提供明确入口。

## 版式

- 目录只展示七个主章节。
- 被合并的内容使用章内小节标题，不再伪装成新的主章节。
- 八步内容继续使用统一账本版式；完整报告与结论来源在同一章中使用清楚的分隔标题。
- 真实界面示例采用与精简版一致的纵向全宽布局，避免提醒中心截图过小。
- 保持现有配色、离线资源、阅读进度、响应式、打印、减少动画和无 JavaScript 能力。

## 验收

- 页面与目录均只有七个主章节。
- DOM 阅读顺序为：价值 → 能力 → 八步过程 → 案例数据 → 报告与依据 → 技术 → 使用。
- 六项产品功能、八步账本、五种数据状态和贵州茅台历史事实完整保留。
- 完整报告和结论来源属于同一个主章节。
- 1440px、736px 和 360px 无页面级横向溢出；打印、减少动画和无 JavaScript 模式正文可读。

## 范围

修改完整版 HTML、对应测试、更新日志和本设计/计划文件；不修改精简版正文、产品代码或历史报告事实源。
