# Web 组合分析任务设计

## 目标

在 Web 首页增加一次点击即可完成“全部自选股分析 → 大盘复盘 → 综合报告 → 可选通知”的组合分析能力。组合流程必须在后端持续运行，页面刷新或关闭不能中断；现有单股分析、批量分析、大盘复盘和 CLI 行为保持兼容。

## 已确认的产品决策

- 第一版固定分析提交时的全部自选股快照。
- 是否发送通知遵循首页“推送通知”开关；关闭时仍生成并保存综合报告。
- 单只股票失败不终止组合任务，其余股票和大盘复盘继续执行；综合报告列出失败项。
- 若提交时存在任一同股任务、正在执行的大盘复盘或其他组合任务，整批拒绝，不创建部分任务。
- 大盘复盘失败时仍生成股票综合报告，并将任务标记为部分完成。
- 第一版不自动关联已有任务，不自动重试，不自动恢复服务重启前未完成的任务。
- 首页使用顶部“综合分析”主按钮。宽屏完整展示所有操作；窄桌面保留推送、综合分析和普通分析，把服务器选择与单独大盘复盘收进“更多”菜单。

## 架构

新增可复用的组合任务编排服务，Web API 与 CLI 完整运行流程共享核心业务语义，不通过 Web 后端启动 `main.py` 子进程。

```text
POST /api/v1/analysis/composite
        |
        +-- 校验并冻结股票、策略、语言、通知和市场区域快照
        +-- 原子检查同股任务、大盘锁与组合任务互斥
        +-- 创建父级组合任务
        |
        +-- 阶段 1：受控并发执行全部股票
        |      +-- 单股失败只记录，不中断
        +-- 阶段 2：执行大盘复盘
        |      +-- 失败后继续生成股票综合报告
        +-- 阶段 3：生成并保存唯一综合报告
        +-- 阶段 4：按 notify 快照决定是否发送通知
```

父任务拥有独立任务 ID。子股票任务记录父任务 ID，普通单股入口也必须把组合任务中的股票视为正在分析。第一版同一时间只允许一个组合任务。

## API 契约

### 提交

`POST /api/v1/analysis/composite`

请求示例：

```json
{
  "stock_codes": ["600410", "600519", "000858"],
  "notify": true,
  "report_type": "detailed",
  "report_language": "zh",
  "skills": ["bull_trend"],
  "market_review_region": "cn"
}
```

页面第一版始终传递当前全部自选股。后端必须验证非空、去重、规范化并限制数量。请求显式携带股票快照，避免运行期间重新读取变化后的自选股。

成功返回 `202`：

```json
{
  "task_id": "composite_xxx",
  "status": "pending",
  "stock_count": 3,
  "notify": true
}
```

冲突返回 `409 composite_task_conflict`，响应包含低敏冲突项：股票代码、已有任务 ID，以及大盘或组合任务冲突标记。冲突时不得创建父任务或任何子任务。

### 状态

组合任务复用现有任务列表、单任务查询与 SSE 生命周期，但增加：

```json
{
  "task_type": "composite_analysis",
  "phase": "stocks",
  "progress": 35,
  "stock_summary": {
    "total": 3,
    "completed": 1,
    "failed": 0,
    "current_stock_code": "600519"
  },
  "market_review": {"status": "pending"},
  "report": {"status": "pending", "history_id": null},
  "notification": {"requested": true, "status": "pending"}
}
```

最终状态：

- `completed`：个股、大盘与报告均成功；通知关闭或发送成功。
- `partial`：部分股票失败、大盘失败或通知失败，但综合报告已生成。
- `failed`：没有任何有效内容或综合报告无法生成。
- `cancelled`：用户取消，后续阶段停止且不发送通知。

状态更新通过现有 SSE 广播，刷新页面后可通过任务列表和父任务 ID 恢复。

## 执行与一致性

- 提交前在任务队列的同一临界区完成全部股票冲突检查与父任务登记。
- 大盘锁与组合任务互斥检查不能在创建部分股票任务后才执行。
- 父任务冻结股票列表、策略、报告语言、报告类型、通知开关和市场区域。
- 股票阶段复用现有分析服务及并发上限，不复制行情、搜索或 LLM 实现。
- 大盘阶段复用现有市场复盘运行时及报告生成器。
- 通知仅在综合报告成功保存后最多发送一次；个股与大盘子阶段不得独立推送。
- 服务重启时，启动恢复逻辑将残留的 `pending` / `processing` 组合任务标记为失败，并给出低敏“服务重启导致中断”原因。

## 综合报告

新增报告类型 `composite_analysis`，报告只保存一次，页面与邮件读取同一份内容：

```text
今日综合分析
├── 执行摘要
│   ├── 成功/失败股票数量
│   ├── 大盘复盘状态
│   └── 数据缺失提示
├── A股大盘复盘（成功时）
├── 自选股决策仪表盘
├── 失败项目（存在时）
└── 生成时间、模型信息与免责声明
```

失败原因只展示经清洗的错误类别和简短信息，不包含密钥、代理地址、完整模型响应或内部路径。

## Web 交互

首页顶部增加“综合分析”按钮，辅助说明为“全部自选股 + 大盘复盘 + 综合报告”。它与股票输入框无关；只有自选股为空、正在提交或检测到不可启动状态时禁用。

点击后直接提交，不增加配置弹窗。请求使用：

- 当前全部自选股快照；
- 当前策略选择；
- 当前报告语言；
- 当前市场区域；
- 首页“推送通知”开关。

任务卡展示四阶段：

```text
综合分析 · 3只股票
● 个股分析  2/3
○ 大盘复盘  等待中
○ 综合报告  等待中
○ 邮件通知  已开启
当前：正在分析贵州茅台
```

完成后提供“查看综合报告”。部分股票失败或大盘失败显示黄色“部分完成”；通知关闭显示普通说明；邮件失败不回滚报告。

若提交冲突，页面列出冲突股票或大盘任务并要求稍后重试，不出现部分提交。

### 响应式工具栏

- 宽屏（建议 `>= 1440px`）：完整显示策略、服务器、推送、大盘复盘、综合分析和分析。
- 窄桌面：始终显示策略、推送、综合分析和分析；服务器与单独大盘复盘进入“更多”菜单。
- 移动端：操作区使用现有换行或折叠菜单模式，保证键盘、屏幕阅读器和触摸操作可用。

## 错误与取消

- 单股失败：继续并写入失败清单。
- 大盘失败：继续生成股票综合报告。
- 报告失败：整体失败，不发送邮件。
- 通知失败：报告保留，任务为 `partial`。
- 取消只允许发生在股票或大盘阶段；停止调度后续工作，不发送通知，已保存的单股历史不回滚。
- 所有异常状态都必须通过任务状态和 SSE 对 Web 可见。

## 测试与验收

后端单元测试覆盖：

- 整批防冲突与零部分提交；
- 父子任务状态和反向去重；
- 部分股票失败继续；
- 大盘失败仍生成报告；
- 通知关闭、通知成功和通知失败；
- 服务重启残留任务收敛；
- 取消边界和敏感信息清洗。

API 测试覆盖请求校验、`202`、`409`、状态序列化、SSE 与取消。集成测试用三只模拟股票验证仅保存一份综合报告、最多发送一次通知。

前端测试覆盖按钮禁用条件、请求快照、响应式工具栏、冲突提示、刷新恢复、四阶段进度、部分完成与通知状态。

验证命令：

```bash
./scripts/ci_gate.sh
cd apps/dsa-web && npm run lint && npm run build
```

手工验收使用三只股票分别验证推送开启与关闭；PR 描述附宽屏/窄屏入口、进行中、部分完成和成功状态截图。

## 文档与兼容性

- 更新 Web 使用文档、API 行为文档和 `docs/CHANGELOG.md`。
- 不改变现有“分析”“分析全部”“大盘复盘”接口和 CLI 参数。
- 新 API、任务类型与首页按钮均为增量能力。
- 回滚时可以移除组合入口和编排 API，原有单股、大盘及 CLI 流程继续可用。

## 非目标

- 自动关联或复用已有单股任务；
- 失败任务自动重试；
- 服务重启后继续执行未完成组合任务；
- 组合任务定时调度；
- 多个组合任务并行；
- 第一版新增独立配置弹窗。
