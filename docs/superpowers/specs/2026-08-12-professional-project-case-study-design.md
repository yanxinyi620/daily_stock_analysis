# DSA 专业项目介绍与完整案例 HTML 设计说明

## 1. 背景与目标

现有 `docs/project-introduction.html` 已能用约 17 分钟介绍 DSA 的定位、功能和技术架构，但内容更接近演示材料，尚不足以独立回答以下专业问题：

- 一份股票分析报告从哪里开始；
- 每个阶段接收什么输入、调用什么工具、产生什么输出；
- 行情、技术指标、新闻、市场环境和模型分析怎样汇合；
- 数据缺失、搜索为空、上游超时和不完整日线如何影响结论；
- 最终报告中的建议、点位、风险与置信度如何溯源。

本次升级将材料重构为可连续滚动阅读的专业专题报告。页面以项目全景为背景，以贵州茅台（600519）的本地历史分析为贯穿案例，完整解释 DSA 如何打造一份分析报告。

材料主要面向产品、技术及非技术混合受众。读者不需要了解 Python、API 或量化分析，即可理解系统的主要能力、工作流程、技术原则和结果边界。

## 2. 成功标准

- 读者能够复述“输入 → 数据 → 指标 → 情报 → 上下文 → AI → 护栏 → 报告”的完整链路；
- 每个案例步骤都明确展示输入、工具、处理、输出、数据质量和下一步去向；
- 最终报告的核心结论能追溯到上游证据；
- 案例只使用当前仓库本地历史记录和报告文件中的可确认事实，不伪装成当前实时分析；
- 页面同时讲清楚正常路径和降级路径，不以“搜索为空”代表“没有风险”；
- 页面适合桌面自读，也能在平板和手机上连续浏览；
- 页面保持离线可用、可打印、支持 reduced motion，并保留清晰的章节导航。

- 数据质量、时效性和不确定性说明；
- 可在 Web 查看、存入历史并通过通知渠道交付的报告。

## 4. 信息架构

页面不再按投屏时间组织，改为以下连续阅读结构。

### 4.1 执行摘要

- 一句话定位 DSA；
- 项目解决的问题；
- 从市场事实到报告交付的价值闭环；
- 本文包含什么、案例数据来自哪里；
- 快速结论：系统不是把原始数据直接交给模型，而是先建立可检查的证据链。

### 4.2 项目能力全景

按照用户目标而不是代码目录介绍：

- 多市场数据与标准化；
- AI 决策报告；
- Web / Desktop 工作台；
- Agent 策略问股；
- 图片、表格、剪贴板导入与代码补全；
- 回测、持仓、历史与告警；
- GitHub Actions、Docker、本地调度、API、Bot 和多渠道通知。

能力全景需要说明各能力如何围绕同一分析与报告链路协作，而不是并列罗列功能。

### 4.3 案例任务定义

- 案例标的、日期、来源和免责声明；
- 用户问题；
- 分析范围；
- 当前已知数据和缺失数据；
- 最终交付标准。

### 4.4 八步端到端案例

每一步使用统一的“工作台账”结构：

1. 本步目标；
2. 输入；
3. 使用的工具或系统能力；
4. 关键处理；
5. 输出；
6. 数据质量与降级；
7. 如何流向下一步。

具体步骤如下。

#### 第一步：标的识别与市场阶段

- 输入：`600519`；
- 工具：代码规范化、市场识别、交易日历、市场阶段判断；
- 处理：识别为 A 股贵州茅台，确定当时处于午间休市、当日日线未完成；
- 输出：标准代码、市场、交易日、分析阶段和时效警告；
- 影响：后续技术结论必须标记为盘中部分数据，不能当作收盘复盘。

#### 第二步：行情与基础事实采集

- 输入：标准代码和市场信息；
- 工具：`DataFetcherManager`、腾讯财经实时行情、历史日线存储、多数据源 fallback；
- 处理：获取当前价、开高低、成交量、量比、换手率和历史日线，并统一字段；
- 输出：标准行情窗口和来源标签；
- 降级：单一数据源失败时尝试适用备用源；所有来源和错误进入诊断记录。

#### 第三步：技术指标与趋势判断

- 输入：实时行情、历史 OHLCV 和市场阶段；
- 工具：`StockTrendAnalyzer`；
- 处理：计算 MA5、MA10、MA20、乖离率、量价状态、支撑、压力与趋势强度；
- 输出：弱势整理、趋势强度 40、乖离率 1.03%、关键点位；
- 降级：盘中未完成日线只作为部分证据，结论需等待午后确认。

#### 第四步：新闻与市场情报

- 输入：公司名称、代码、新闻时间窗和风险检索维度；
- 工具：`SearchService`、SearXNG、公告/机构/风险/业绩维度搜索；
- 处理：检索、去重、筛选时效并形成情报摘要；
- 输出：近 3 日没有可确认样本；
- 降级语义：搜索为空表示“当前没有检索到可确认信息”，不表示不存在风险，也不能生成虚构催化。

#### 第五步：基本面、板块与数据质量

- 输入：实时估值、基本面 bundle、板块信息、筹码和资金数据；
- 工具：基本面上下文、市场结构服务、板块适配、数据质量状态；
- 处理：区分 available、partial、missing、failed 和 empty；
- 输出：估值可用，部分基本面、资金、筹码和题材证据不完整；
- 降级：缺失维度不参与强结论，并进入限制清单和置信度解释。

#### 第六步：Analysis Context Pack

- 输入：行情、日线、技术、新闻、基本面、板块、市场阶段与诊断；
- 工具：`AnalysisContextBuilder` / `AnalysisContextPack`；
- 处理：按稳定结构组织证据，记录每个 block 的状态、来源、警告和缺失原因；
- 输出：模型可消费的证据包和数据质量摘要；
- 影响：模型只根据已提供证据分析，同时看到哪些证据不完整。

#### 第七步：AI 综合研判与规则护栏

- 输入：上下文包、报告结构要求和交易纪律；
- 工具：LLM Analyzer、字段完整性修复、市场阶段护栏、趋势和追高规则；
- 处理：形成初稿，并检查操作建议与趋势、乖离率、支撑止损、数据时效是否冲突；
- 输出：观望 / 震荡、空仓和持仓建议、风险、催化、买入观察区、止损与目标；
- 降级：字段缺失时补安全占位或确定性 fallback，不以宽泛结论掩盖未知信息。

#### 第八步：报告、历史、诊断与通知

- 输入：最终结构化结果；
- 工具：Report Renderer、History Service、Diagnostics、Notification Service；
- 处理：渲染 Markdown / Web 报告，保存原始结果和上下文快照，记录数据源、模型和通知运行；
- 输出：完整报告、历史记录、诊断证据和通知摘要；
- 失败隔离：报告保存与单一通知渠道相互解耦；通知失败不抹掉分析结果。

### 4.5 最终报告成品

使用 HTML 重建一份完整、可阅读的贵州茅台案例报告，而不是依赖旧截图。报告至少包括：

- 案例标识与数据时点；
- 核心结论、趋势、评分与置信度；
- 空仓者与持仓者建议；
- 当日行情表；
- 均线、量价、支撑和压力；
- 数据可用性提示；
- 盘中决策护栏和观察条件；
- 理想买入、次优买入、止损、目标和仓位；
- 新闻、风险、催化；
- 检查清单；
- 信号归因；
- 免责声明。

旧的真实产品截图作为“最终结果在产品中的呈现方式”旁证保留，但不承担案例正文。

### 4.6 报告溯源矩阵

| 报告结论 | 上游证据 | 处理规则 |
| --- | --- | --- |
| 观望 | MA5 < MA10；盘中日线未完成；部分数据缺失 | 不满足趋势入场条件时不追买 |
| 震荡 | MA5 / MA10 / MA20 结构与价格位置 | 趋势未形成一致方向 |
| 买入观察区 1331.71–1336.47 | MA5 与 MA10 | 仅在回踩、缩量、止跌后重新评估 |

### 4.7 技术实现与稳定性

保留四层架构，但围绕案例数据流解释：

## 5. 视觉与交互设计

### 5.1 视觉基调

保留确认过的 A × B 混合方向，但从演示材料转为研究报告：

- 深海军蓝用于执行摘要、数据链路和关键决策；
- 暖纸色用于正文、案例账页和最终报告；
- 绿色、金色、朱红只用于状态和证据强调；
- 增加更窄的正文列、更明确的脚注、来源标签和表格层级；
- 减少满视口章节和大标题，增加连续阅读密度；
- 不使用通用 KPI 卡片墙或装饰性仪表盘堆叠。

### 5.2 导航与阅读

- 顶部提供执行摘要与完整目录；
- 桌面端使用吸附章节导航，移动端使用可横向浏览的章节目录或紧凑目录按钮；
- 取消方向键章节切换和讲解分钟数；
- 保留阅读进度；
- 支持点击“查看输入 / 查看输出”在同一案例步骤内展开补充业务表格，但默认页面无需交互也能完整阅读；
- 所有关键信息在打印与无 JavaScript 场景可见。

### 5.3 核心图解

1. 数据血缘图：标的输入到最终报告的八步数据流；
2. 数据质量矩阵：available / partial / missing / failed / empty 的含义与处理；
3. 报告溯源矩阵：报告字段、上游证据和护栏规则的映射；
4. 案例价格位置图：当前价、MA5、MA10、MA20 和压力位在同一尺度上的位置；
5. 工具链地图：真实系统能力及其业务职责。

图解使用 HTML/CSS/内联 SVG，不加载在线图库或图表库。

## 6. 事实与表述边界

- 使用 2026-08-12 报告中的案例值时，必须显示历史日期和“演示案例”；
- 不使用旧永鼎股份截图作为当前案例；
- 不声称新闻为空等同于没有风险；
- 不虚构当前新闻标题、模型准确率、实时价格、耗时或数据源成功率；
- 工具名称来自当前仓库实现，但面向用户使用通俗职责说明；
- 当数据库中的历史记录和报告 Markdown 存在差异时，案例成品以 `reports/report_20260812.md` 为展示基线，上游链路与质量状态使用相同日期的数据库快照补充；
- 所有建议均是历史示例，不构成当前投资建议。
