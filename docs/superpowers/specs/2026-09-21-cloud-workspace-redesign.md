# 云端工作台布局与记录操作设计

状态：用户已确认布局、状态合并和可恢复删除；补充要求为个股报告直接显示股票名称，缺少名称时显示代码，不添加“个股分析”前缀。

## 目标与推荐布局

复用现有 React 云端页面与深色主题，采用紧凑的左右工作台布局：左侧约 250px 自选股列表，右侧上方发起分析、下方分析记录。缩小大标题和留白，账户入口固定在顶栏右侧；修改密码使用弹窗。添加、编辑自选股也改为按需弹窗，保留市场、代码、名称和排序能力。

窄屏按自选股、发起分析、分析记录顺序排列，表格区域独立横向滚动。分析服务状态显示人类可读的在线、离线或忙碌，最近连接时间不直接显示原始时间戳。任务执行、离线保护、重试和轮询逻辑保留；完成任务不在首页重复铺开历史列表，尚未生成报告的进行中或失败任务仍能查看。历史任务入口可折叠，并保持可访问。

备选方案：上下全宽卡片更容易实现但页面较长；独立“自选股／分析／报告”分页更适合后续大规模功能，当前增加操作跳转。因此推荐左右工作台。

## 记录表与统一状态

列为：报告名称、来源、状态、时间、操作。时间仅显示日期和时分，移除“报告生成／状态更新”副文案。排序规则保持现有任务更新时间倒序。

保存状态优先表达是否已留存；已保存后再根据可信执行摘要细分：

- publishing：保存中；publish_failed：保存失败；cancelled：已取消。
- 已保存且综合摘要 completed：已完成；partial：部分完成。
- 已保存且非综合执行成功：已完成。
- 报告已保存但缺少执行信息／可信摘要：已保存，不推断全部成功。
- 已保存但执行失败等不一致历史：结果待确认，并可通过说明查看原始含义。

“已完成／部分完成”只在保存成功时显示，保留缺失报告的异常反馈；查看与下载只在报告实际存在时可用。

## 删除推荐：可恢复删除

操作增加“删除”，点击后确认移入回收站；提供回收站入口和恢复操作。不自动清空，不永久删除既有报告、附件、执行历史或引擎历史。设计稿的所有记录均为示例，按钮不操作真实账户。

需要新增增量迁移记录删除标记（例如 analysis_tasks.deleted_at），禁止普通用户直接修改任务状态或报告正文；仅通过严格校验 auth.uid 与启用成员身份的受限操作设置／清除标记。匿名、B 用户操作 A 记录及停用成员均必须拒绝。进行中的任务禁止删除，发布重试与删除的并发契约必须在数据库锁下保持一致，不允许后台重试自动恢复已删除记录。

普通列表、计数与轮询过滤回收站记录；回收站仍限本人查看与恢复。本人报告和附件继续受现有 RLS 与私有 Storage 授权保护；移入回收站不等于永久撤销本人已有深链访问。执行历史中的报告入口也要说明回收站状态，避免用户误认为删除未生效。该方案不更改 Python 分析逻辑，不新增平台付费资源。

永久删除作为未选备选：需协调 Storage 附件清理、数据库引用及幂等失败恢复；不能直接开放数据库 DELETE 后宣称附件已清理。本轮默认不包含该方案，待用户选择。
