# 选股历史记录设计

## 目标

让用户在选股页面查看已经持久化的选股运行记录，并能将任一历史记录恢复到现有“运行信息 + 选股结果”区域中。

## 交互设计

- 选股结果区域提供“当前结果 / 历史记录”两个页签。
- 首次进入页面仍展示当前结果，不改变现有运行流程。
- 切换到历史记录时请求最近 20 条记录，展示时间、策略、市场、快照数量、过滤后数量、候选数量和排序方式。
- 点击“查看结果”后请求该次运行详情，将候选与运行元数据加载到当前结果区域，并自动切回“当前结果”。
- 新任务完成后刷新历史列表；历史加载或详情加载失败仅在历史区域提示，不影响运行新任务。
- 没有历史记录时展示明确空状态；候选数为 0 的运行仍可打开并查看诊断信息。

## 数据流

页面复用现有 `screeningApi.getHistory()` 与 `screeningApi.getRun()`。历史摘要只负责导航，完整候选数据始终以详情接口为准。现有 `applyScreenResult()` 作为当前结果的唯一写入入口，避免历史恢复与实时任务形成两套展示状态。

## 验证

- 页面测试覆盖历史加载、摘要字段、点击恢复详情、空状态和错误状态。
- 运行选股页面测试、前端 lint 和生产构建。
