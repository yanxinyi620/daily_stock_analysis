# Runner 综合分析增量计划

沿用已批准的 [本地 Runner 方案](../../deployment/vercel-supabase-plan.md)，复用 `CompositeAnalysisService`，不改 Actions、不切生产、不删除历史、不提交代码。

1. 新增 `composite_analysis`，网页仅提交单市场复盘 region。数据库在同一提交事务读取本用户自选股，按 position/id 固定代码与自选股信息；空列表拒绝，输入不接受客户端股票列表。重复请求返回原快照，之后编辑自选股不改变已提交任务。
2. 复用现有组合编排。云端模式关闭额外本地报告和通知、旧 CLI 发布，按单工作线程执行；租约失效后不再开始后续股票。各成功子报告必须有历史；未持久化项按失败处理。组合历史保存后才发布。
3. 以原状态 succeeded 表示“报告已发布”，新增原子保存的 result_summary 表示业务结果 completed/partial，包含成功/失败数量、失败代码和复盘状态；页面和报告明确显示部分完成，完全失败不发布成功报告。发布包保存摘要，上传重试不重跑模型。
4. 私有历史 report_type 从 varchar(16) 扩到 varchar(32)，兼容已有 composite_analysis 标识；新增迁移，不改旧迁移或清空数据。
5. 扩展前端任务类型、快照说明、部分完成与失败明细；保留离线/未知/忙碌保护及不确定提交锁定。
6. 隔离后端测试、SQL/API/前端回归、构建；在恢复项目和 Vercel Preview 完成一次小规模真实综合分析、报告留存/下载和权限验收。远端测试自选股仅在空测试列表中追加明确的验证样本并保留，不覆盖用户已有记录。

回滚：停止新 Runner、回退前端；保留新增表列和历史。旧 Runner 只识别旧任务类型，升级时先停止旧进程，再迁移、更新 Runner 和前端。
