01 / 项目价值

项目解决什么问题

本章回答：为什么需要这套系统，它适合谁，又有哪些明确边界？

用户输入股票代码后，DSA 会获取行情、计算技术指标并查找相关新闻。系统先核对数据是否完整，再让模型根据已有数据整理说明。最后，用户会在 Web、桌面端或通知消息中看到结论、理由、风险和需要继续观察的条件。

8 步过程看得见从输入代码到保存报告，每一步都说明拿到了什么、做了什么。
5 种数据状态区分可用、部分可用、缺失、失败和结果为空，不把未知写成确定。
3 层决策表达事实层、解释层、行动层彼此分开又能相互追溯。
先算清楚，再写结论。
价格、均线和交易时段由程序计算或核对。模型负责把这些数据讲清楚，但不能改动数字，也不能忽略缺失的数据。

这个系统不承诺预测涨跌。它主要减少重复工作：自动收集多个来源的行情，计算指标，查找新闻，指出缺少哪些资料，再给出有条件的操作建议。报告可以保存、分享，也可以继续设置提醒。

功能怎样配合

从发现股票，到持续跟踪

这些功能并不是重复做同一份报告。选股负责缩小范围，每日综合分析负责找出当天重点，单股分析负责深入查看，问股负责继续追问，回测负责检查历史表现，自选股和提醒负责把关注延续到下一天。

01 · 发现

选股

按价格、指标、题材或内置策略筛出候选股票，先把研究范围缩小。

02 · 浏览

每日综合分析

批量分析自选股，并结合大盘复盘，找出当天需要优先查看的股票。

03 · 深入

单股分析

获取一只股票的行情、技术指标和新闻，形成关键价位与风险说明。

04 · 追问

问股

针对已有报告继续提问，例如为什么观望、什么条件下需要重新判断。

05 · 检查

回测

查看历史报告或策略在后续行情中的表现，检查判断是否经常有效。

06 · 跟踪

自选股与提醒

保存需要继续关注的股票和价位条件，进入下一次每日分析。

完成一次跟踪后，新的行情和提醒结果会成为下一轮研究的起点。

功能拿到什么主要解决什么问题得到什么常见下一步
选股市场范围、筛选条件或策略股票很多，先看哪些候选股票列表和命中理由打开候选股的单股分析，或加入自选股
每日综合分析自选股、大盘信息和当天任务设置今天先看哪几只、整体市场怎样个股执行结果、大盘复盘和综合报告进入重点股票的详细报告
单股分析股票代码、行情、历史价格和新闻这只股票当前处在什么位置结论、理由、关键价位、风险和观察条件继续问股，或设置关键价位提醒
问股用户问题和已经保存的分析资料报告中还有哪些问题需要讲清楚针对问题的解释和后续检查项返回报告核对，或查看历史表现
回测历史分析、策略规则和后续行情过去类似判断表现怎样历史任务、结果和统计汇总调整关注条件，再进行新的研究
自选股与提醒候选股票和需要观察的价位怎样持续关注，而不是只看一次自选股列表、批量分析任务和提醒记录进入下一次每日综合分析

05

基本面、板块与数据质量

部分可用（partial）
这一步要做什么
继续获取估值、基本面、板块、筹码和资金数据，并检查是否完整。
拿到什么
实时估值、基本面资料包、板块信息、筹码和资金数据。
使用什么
基本面资料、市场结构服务、板块数据和数据状态检查。
怎样处理
分别标记可用、部分可用、缺失、失败和结果为空，并写明哪些资料不能用于强结论。

数据不足怎么办
整体只有部分数据可用。分析仍可继续，但报告会降低把握程度，并明确说明缺少什么。
接下来交给谁
把各类数据和状态交给资料整理程序。
可用（available）

数据已经拿到，可以直接使用。本例是报价和均线数值。

部分可用（partial）

只拿到一部分资料。报告会降低把握程度，并说明限制。

缺失（missing）

没有拿到这项数据。报告不能自行补写具体事实。

失败（failed）

获取或计算时发生错误。系统会记录原因，并尝试其他方法。

结果为空（empty）

工具运行正常，但没有找到内容。搜索为空不等于没有风险。

05 / 最终报告与结论依据

最终报告与结论依据

本章回答：最终报告怎样表达事实、判断和行动条件，每项结论又来自哪些数据？

下面把历史记录重构为一份完整的人类可读报告。它保留原始结论与数值，同时把事实、判断和限制分层。

历史分析报告

贵州茅台（600519）

2026-08-12 · 午间快照 · 腾讯财经
1345.43
建议：观望走势：震荡评分：54 / 100把握程度：中等（中等置信度）
一句话结论
MA5、MA10、MA20 分别表示最近 5、10、20 个交易日的平均价格。当时价格高于这三条均线，但 5 日均价仍低于 10 日均价，短期上涨还不够稳定；趋势强度只有 40。由于当天尚未收盘，报告建议先观察，不在价格刚上涨时追买，等关键价位出现更明确的信号再行动。

当日行情

昨收 1348.86 · 开盘 1346.50 · 最高 1354.01 · 最低 1332.51 · 量比 0.96 · 换手率 0.14%

成交量 175.78 万股，成交额 23.61 亿元。以上均为午间实时快照，非完整日线。

市场与技术结构

  • 当时价格 / 涨跌1345.43 / -0.08%
  • MA51331.71
  • MA101336.47
  • MA201316.86
  • 现价高于 5 日均价+1.03%，偏离不大
  • 第一压力 / 目标1354.01

空仓计划

不在 1345.43 附近追高。等待两类确认之一：

  1. 价格回到 1331.71–1336.47 区间时，成交量减少，并且不再继续下跌；
  2. 价格升到 1354.01 以上时，成交量明显增加，并在盘中或收盘时仍站在该价位上方。

仓位：空仓者 0 成观察；确认后不超过 2 成。未出现确认信号前保持观望。

持仓计划

价格保持在 20 日平均价 1316.86 之上时，可以继续观察持有。如果价格跌到 1316.86 以下，同时成交量明显增加，说明下跌力度较强，应按计划减仓或止损。接近 1354.01 时，要同时观察价格能否站稳、成交量是否增加，不能把短暂触碰当成真正突破。

仓位：持仓者控制在 5 成以内，并预留 T+1 的隔夜风险缓冲。

关键决策点

  • 理想买入点1331.71，止跌承接后
  • 次优买入点1336.47，回踩不破后
  • 止损位1316.86，跌破且无法快速收回
  • 目标 / 上方阻力1354.01，价格站稳且成交增加后再评估

新闻、风险和可能的利好

近 3 日搜索没有找到可确认的新闻，因此报告没有据此判断利好或利空。没有搜到新闻，并不等于公司、行业或宏观层面没有风险。

主要风险：当天还没有收盘、新闻搜索没有结果、筹码数据缺失，部分资金和基本面资料也不完整。

行动检查单

  • 价格回到 1331.71–1336.47 后，是否停止下跌？
  • 价格升到 1354.01 以上时，成交量是否明显增加？
  • 价格跌到 1316.86 以下时，成交量是否明显增加？
  • 收盘后均线和成交量是否仍支持盘中判断？
  • 是否出现新的公司公告或行业事件？

盘中检查规则：最后一根日线未完成，任何盘中突破或跌破都要结合量能，并在收盘后复核。

06 / 技术实现与系统边界

系统怎样实现，并在出错时保留结果

本章回答：任务怎样进入系统、数据怎样分析、报告怎样保存，以及单个环节失败时如何处理？

系统把工作分成四部分：接收任务、安排分析步骤、获取并分析数据、保存报告和发送通知。这样更容易找到问题，也能避免一个环节出错后影响已经完成的工作。

使用入口
Web · Desktop · CLI · API · Bot · Scheduler
用户可以从不同入口发起同一种分析任务，并得到相同格式的结果。
任务处理
Pipeline · Services · Schemas · Repositories
安排先做什么、后做什么，记录任务状态，并读写历史报告。
数据和分析
DataFetcherManager · StockTrendAnalyzer · SearchService · AnalysisContextPack · LLM Analyzer · Guardrails
切换数据源、计算指标、搜索新闻、检查数据状态，并由模型整理说明。
保存与通知
Report Renderer · History Service · Diagnostics · Notification Service
生成并保存报告，记录错误；某个通知渠道失败时，已完成的报告仍会保留。

一个数据源失败时

系统会按顺序尝试备用行情源，再把不同来源的数据整理成相同格式。报告会保留实际使用的数据来源。

数据不完整时

系统会区分是部分可用、完全缺失、获取失败，还是工具正常运行但没有结果。不同状态会影响报告的把握程度和用词。

一个环节出错时

新闻搜索或某个通知渠道失败，不会推翻已经完成的行情和技术分析。运行记录工具 Diagnostics 会保存错误位置和原因，方便排查。

07 / 使用方式与限制

怎样使用，以及哪些事不能依赖它

本章回答：个人、团队和自动任务怎样使用系统，哪些结果必须复核，哪些事情系统不能承诺？

DSA 可以帮助用户收集资料、计算指标和整理检查项。它不能保证未来收益，也不能替代用户核对数据、判断风险和做出最终决定。

个人研究

输入股票代码后，先看结论，再查看结论使用了哪些数据。把关键价位加入提醒，不要只保存一句“买”或“卖”。

团队协作

产品人员关注报告是否好读、建议能否继续跟踪；技术人员关注数据是否正确、失败时怎样处理；其他参与者可以通过完整案例理解系统能做什么、不能做什么。

自动运行

通过定时任务、API 或 Bot 批量执行；先配置数据源与模型，再验证通知渠道和历史留存。
